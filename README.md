# Сайт Евгения Куницкого

Персональный сайт-визитка управляющего ГК «ТрансСтрой Девелопмент» (ГК «ТСД»).

План работ по проекту — `Сайт-Куницкого-план.xlsx` в корне репозитория.

Одностраничник с 3D-анимацией на первом экране, скролл-анимациями по всем
секциям и четырьмя языками (RU / EN / 中文 / العربية, включая RTL).

## Запуск

```bash
npm install
npm run dev        # разработка, http://localhost:3000
npm run build      # production-сборка в папку out/
```

Сборка статическая (`output: 'export'`) — в `out/` лежат обычные файлы,
их можно положить на любой хостинг. Node.js на сервере не нужен.

## Вступительная анимация

Первый экран — сцена на WebGL. Порядок кадров:

1. проступает сетка чертежа;
2. на площадку встают сваи и уходят в грунт ударами копра;
3. от центра разливается плита основания;
4. волной идут работы: каркас и сразу за ним бетон, у высоток стоят краны;
5. город обживается, зажигаются окна;
6. камера отъезжает, начинается снег.

Каркас и бетон намеренно живут в одной фазе. Пока это были две стадии,
весь город успевал встать скелетом раньше, чем появлялся первый бетон:
полторы сотни просвечивающих домов складывались в сетку линий, за которой
не читалось ничего.

Всё, что делает картинку похожей на застройку, а не на схему, держится на
двух решениях. Первое: дома стоят по уличной сетке кварталами, а не
россыпью (`cityLayout.ts`). Второе: и рост, и окна, и перекрытия считаются
в этажах — поэтому окна на высотке и на пятиэтажке одного размера, а дом
растёт захватками, а не тянется вверх резиновым.

Первые ~4,6 секунды сцена играет сама, страница в это время заблокирована,
есть кнопка «Пропустить». Дальше анимацией управляет скролл.

Разметка фаз — в `src/components/hero/heroState.ts`, маршрут камеры —
в `src/components/hero/CameraRig.tsx` (правится по ключевым кадрам).

### Производительность

Бюджет сцены выбирается по устройству (`src/lib/useDevice.ts`):

| | телефон / слабое железо | десктоп |
|---|---|---|
| зданий | 90 | 190 |
| свай | 360 | 760 |
| башенных кранов | нет | 5 |
| снежинок | 1400 | 5000 |
| pixel ratio | до 1.35 | до 1.6 |
| сглаживание | выкл | выкл |

Поверх этого работает подстройка по факту (`AdaptiveQuality.tsx`): если
кадры стабильно длиннее 24 мс, плотность пикселей понижается ступенями,
а краны отключаются. Признаки устройства врут в обе стороны — ноутбук со
встроенной графикой выглядит как мощная машина, — поэтому решает
измеренное время кадра, а не догадка о железе.

Сцена рисуется только пока первый экран в кадре. Дальше по странице цикл
останавливается: он не виден, но забирал кадры у скролл-анимаций в
секциях, и это ощущалось как подтормаживание всего сайта.

Достроенный город переводится в непрозрачный проход. Это самая дорогая
деталь сцены: с уровня улицы за каждым фасадом стоит ещё десяток, и в
прозрачном проходе шейдер считался для всех, хотя видно только ближний.

При системной настройке «уменьшить движение» вступление пропускается
и показывается финальный кадр.

Three.js грузится отдельным чанком, пока на экране прелоадер: стартовый
бандл — 167 КБ вместо 409 КБ.

## Цвета

Тёмная база и один холодный акцент — лёд и сталь. Единственный источник
правды для 3D-сцены — `src/lib/palette.ts`; те же значения продублированы
для вёрстки в `tailwind.config.ts` и в переменной `--signal`.

Внутри сцены объекты различаются **яркостью одного тона**, а не разными
цветами: сетка чертежа → контур здания → сваи → окна. Второй оттенок в
кадре сразу читается как «нарядно», а не «солидно».

Крупная типографика (фамилия на первом экране, вторая строка прелоадера)
идёт приглушённым `signalMuted`: чистый акцент на таком кегле выглядит
неоново.

## Контент

Все тексты — в `src/content/{ru,en,zh,ar}.ts`, структура задана типом
`Content` в `src/content/types.ts`. Вёрстка текстов не содержит: чтобы
позже подключить админку, менять компоненты не придётся.

Добавляете поле — добавьте его в `types.ts`, тогда TypeScript сам
покажет, в каких языках его не хватает.

## Проверка вёрстки

```bash
npx serve out -l 4173
node scripts/shoot.mjs http://localhost:4173/ /tmp/shots
```

Снимает экраны на десктопе и телефоне в пяти точках прокрутки героя и на
каждой секции. 3D-сцену тестами не покроешь — «поехавшую» камеру или
невидимый текст видно только на картинке.

## Превью по ссылке

На боевой хостинг едет обычная сборка из `out/`. Но чтобы показать сайт
заказчику ссылкой, нужен один самодостаточный файл: площадка публикации
не пропускает никаких внешних запросов — ни за скриптом, ни за шрифтом,
ни за фотографией.

```bash
npm run preview   # next build + склейка в preview/index.html
npm run verify    # браузерная проверка того, что публикуется
```

Отдельно проверяется, что собрались шейдеры: неудачная компиляция не
видна на снимке — объект просто пропадает из кадра, а всё остальное
продолжает работать.

`verify` поднимает свой сервер, оборачивает файл ровно как площадка, и
проверяет на десктопе и на телефоне: поднялся ли WebGL, доиграл ли
прелоадер, все ли фото вшиты и не ушло ли наружу ни одного запроса.
Отдельно проверяется арабская версия — там переворачивается вся раскладка.
С флагом `--shots <каталог>` попутно снимает экраны.

Сам `preview/` в репозиторий не коммитится: это сгенерированный файл на
5 МБ, который собирается из `out/` за один прогон.

## Показать заказчику по ссылке

```bash
node scripts/publish-pages.mjs
```

Собирает сайт и выкладывает его в ветку `gh-pages`. Адрес получается вида
`https://<владелец>.github.io/<репозиторий>/`.

Первый раз нужно один раз включить публикацию: настройки репозитория →
Pages → Source: Deploy from a branch → ветка `gh-pages`, папка `/ (root)`.

Сборка для подпапки идёт с переменной `BASE_PATH` (см. `next.config.mjs`):
без префикса браузер искал бы скрипты и стили в корне домена. Пути к
фотографиям лежат в текстах обычными строками, поэтому их префиксует
`src/lib/asset.ts` — Next сам это делает только для `next/image`.

На боевой хостинг едет обычная сборка без `BASE_PATH`.

```

  content/        тексты на 4 языках + ссылки
  lib/            i18n, определение устройства

    hero/         3D-сцена: город, сваи, плита, краны, снег, камера
```
